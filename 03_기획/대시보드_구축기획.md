## 대시보드 정의와 역할

### 정의

> **브랜드 인지도 진단·모니터링 대시보드**
>
> 과거 및 현재 데이터를 통해 이니스프리의 브랜드 인지도 저하 현상과 원인을 진단하고, 동일한 핵심 지표를 지속적으로 추적하여 향후 브랜드 인지도의 회복 여부를 확인하는 대시보드.

단순 "성과 모니터링 대시보드"도, 단순 "문제 분석 대시보드"도 아니다. 제안서 자체가 매출·수익성이 아니라 브랜드 인지도 문제로 스코프를 명확히 잡고 있고([인지도범위_판단가이드라인.md](인지도범위_판단가이드라인.md)), 마지막에는 같은 지표를 계속 추적하는 모니터링 단계로 연결되기 때문에 이 두 성격이 하나의 대시보드 안에 함께 있어야 정확하다.

### 3가지 역할

| 역할 | 질문 | 대시보드가 하는 일 |
|---|---|---|
| **진단** | 이니스프리 브랜드 인지도에 어떤 문제가 있었는가? | 과거 검색 관심도, 제품-브랜드 격차, 제주 연상, 접점 감소 등을 시계열로 확인 (→ 화면 1) |
| **근거 제시** | 왜 이런 리브랜딩 전략이 필요한가? | 문제 데이터를 전략 및 랜딩/상세페이지 제안의 근거로 연결 |
| **모니터링** | 이후 브랜드 인지도가 회복되고 있는가? | 동일 KPI를 지속 업데이트하여 상승·하락 추적 (→ 화면 2) |

흐름은 **Problem → Evidence → Strategy → Monitoring**이다. 이 구조의 핵심은 제안 전에 쓴 데이터를 제안 이후 버리지 않고 그대로 성과 측정 지표로 재사용한다는 것 — "브랜드 검색지수 하락 → 문제 발견 → 회복 전략 제안"이었던 흐름이, 제안 승인 이후에는 "브랜드 검색지수 지속 추적 → 반등 여부 확인 → 전략 방향 검증"으로 바뀐다. 화면 1(분석 재현)과 화면 2(KPI 모니터링)를 굳이 나누지 않고 하나의 대시보드로 묶어 둔 이유도 이것이다.

### Dashboard Overview (UI 문구)

상단 설명용(긴 버전):

> **이니스프리 브랜드 인지도 진단 및 모니터링 대시보드**
>
> 공개 데이터를 기반으로 이니스프리의 브랜드 검색 관심도, 제품-브랜드 관심 격차, 제주 헤리티지 연상 등 주요 브랜드 인지도 지표를 지속적으로 수집·분석합니다.
>
> 과거 데이터에서는 브랜드 인지도 저하와 주요 문제를 진단하여 리브랜딩 전략의 근거로 활용하고, 이후 동일한 KPI를 지속적으로 모니터링함으로써 브랜드 인지도의 변화와 회복 여부를 확인합니다.
>
> 각 데이터는 정기적으로 갱신되며, 마지막 업데이트 시점을 함께 제공합니다.

인라인용(짧은 버전):

> 공개 데이터를 기반으로 이니스프리의 브랜드 인지도 현황과 변화를 추적합니다. 과거 데이터로 문제를 진단하고, 동일 KPI를 지속적으로 모니터링하여 브랜드 인지도 회복 여부를 확인합니다.

"실시간 마케팅 성과 관리"처럼 쓰지 않는다 — CTR·CVR·ROAS 같은 이니스프리 내부 데이터가 없으므로, 공개 데이터 기반 진단·모니터링이라는 스코프를 문구에서도 그대로 지킨다.

> ⚠ **문구와 실제 v1 범위를 항상 맞춘다.** "경쟁 브랜드 대비 관심도"는 아직 실측 KPI가 아니라 가설 단계([Competitive Search Share](#가설--보류--정리만-해두고-실-kpi에는-미반영), 동음이의 오염 검증 전)이므로 Overview 문구에서 뺐다 — 만들지 않은 걸 만든 것처럼 말하지 않는다. "자동화된 데이터 수집"도 마찬가지로 뺐다: 스케줄러 담당자가 아직 미정([4장](#4-기술-스택-메모))이라 v1은 정기 수동·반자동 갱신이 현실이고, 완전 자동화는 v2 로드맵([5장](#5-로드맵--v1-vs-v2))에서 다룬다. 두 문구 다 실제 구축 범위가 따라잡으면 그때 다시 넣는다.

### OKR 구조

대시보드를 만드는 것 자체를 Objective로 잡지 않는다 — 대시보드는 수단이고, 목적은 브랜드 인지도를 진단하고 회복 여부를 지속 판단하는 것이다.

**Objective — Brand Awareness Recovery**
> 데이터를 기반으로 이니스프리의 브랜드 인지도 문제를 진단하고, 브랜드 인지도 회복 여부를 지속적으로 측정할 수 있는 모니터링 체계를 구축한다.

> **v1 범위 확정(마감 2026-08-30 기준)**: 아래 KR1~3만 v1 OKR로 확정한다. 열려 있던 조사 과제(경쟁/카테고리 벤치마크, 월별 해상도 반응성 확인)는 마감 안에 답이 나온다는 보장이 없어 **v1에서는 하지 않기로 결정**하고 v2로 이월한다. "조사해보고 결정"으로 열어두지 않고 지금 확정해야 팀이 실제로 화면을 만들 수 있다.

| KR (v1 확정) | 내용 | 목표 설정 방식 | 담당 KPI |
|---|---|---|---|
| **KR1 — Brand Awareness** | 브랜드 검색 관심도의 월별·전년 동기 대비 변화율을 지속 추적한다 | [0-1장](#0-1-kpi-목표치-90--180--360일-게이트) 90/180/360일 게이트 그대로 사용 | 브랜드 검색지수 |
| **KR2 — Brand Association** | 제주·그린티 등 핵심 헤리티지 연상 지표의 변화 추이를 지속 측정한다 | 원자료 값이 아니라 **자연 추세선(연평균 +0.27%p) 대비 초과분**만 성과로 인정(0-1장 방식 그대로, 추가 검증 없이 확정) | "제주" 연상 비중 |
| **KR3 — Brand Conversion** | 제품 관심도와 브랜드 관심도의 격차(Product–Brand Gap)를 지속 측정한다 | Gap 숫자만이 아니라 제품·브랜드 두 성장률을 항상 같이 표시. **브랜드 성장률이 마이너스면 Gap 축소를 성공으로 인정하지 않음**(가드 조건 확정) | 제품↔브랜드 Gap |

**v1에서 빼기로 확정한 것** (조사 과제로 열어두지 않음):
- **KR4(경쟁 지위)는 v1 OKR에서 제외.** 동음이의 오염 없는 벤치마크를 찾을 수 있을지 몰라서가 아니라, 마감까지 그걸 검증할 시간이 없어서 안 한다. Competitive Search Share는 계속 "가설/보류" 표에만 남기고, v2에서 시간 있을 때 다시 본다
- **KR2 월별 해상도 재검증도 v1에서 안 한다.** 연 단위 자연 추세선 대비 초과분 방식으로 확정하고 그대로 build 한다
- **KR5(자동 수집·갱신 시각)는 애초에 OKR이 아니라 화면 2 카드 요구사항으로 확정.** 재논의 필요 없음

**AEO/SEO 대응 상태**(실측 KPI 4위)는 계속 KR 목록 밖에 둔다 — 소비자 인지 변화가 아니라 "회사가 실행을 했는가"를 판정하는 실행 지표라 화면 2에서 성과 3지표(상단)와 별도 구역(중단)으로 분리한다.

**v1 착수 전 필수 작업은 없다.** 원래 여기 "KR1 baseline API 재조회"를 필수 작업으로 적어뒀는데, 확인해보니 [네이버데이터랩_검색량_분석_2021-2025.md](../02_수집자료/네이버데이터랩_검색량_분석_2021-2025.md)에 2025년 실측치(2.30)가 이미 있었다 — [0-1장](#0-1-kpi-목표치-90--180--360일-게이트) 표도 이 값으로 갱신했다. v1 KR 3개는 지금 바로 실측 데이터 기준으로 build 가능하다.

정리하면:

> **OKR = 우리가 달성하려는 것 / KPI = 달성 여부를 판단할 숫자 / Dashboard = KPI를 지속적으로 관찰하는 도구**

### 포트폴리오 전체 흐름 속 위치

```
Problem                브랜드 검색 하락 / 제주 연상과 커뮤니케이션의 괴리 / 제품-브랜드 단절
  ↓
Dashboard               문제를 데이터로 진단하고 지속 모니터링   ← 이 문서가 다루는 범위
  ↓
Insight                 "브랜드 자산은 사라진 것이 아니라 연결되지 않고 있다"
  ↓
Strategy                증명된 헤리티지
  ↓
Execution               랜딩페이지 / 상세페이지 / 캠페인
  ↓
KPI Monitoring          Brand Search / Heritage Association / Product–Brand Gap / Competitive Search
```

제안서의 "문제 A~F → 시장분석 → 포지셔닝 → 크리에이티브 → 실행"([제안서_본문.md](제안서_본문.md)) 구조와 그대로 이어진다. 포트폴리오에서 이 대시보드를 소개할 때는 "데이터 분석 결과물"이 아니라 **Brand Awareness Monitoring Dashboard**(또는 Strategy Intelligence Dashboard)로 명명하고, "진단에서 시작해 전략 실행 이후 성과까지 같은 KPI로 추적한다"고 설명하는 편이 완성도가 높다.

## 0. KPI 재검토 결과 요약

팀원이 정리한 데이터 소스 표(우선순위 S/A/B, 자동화 방식별)와 ChatGPT가 제안한 8개 KPI 후보를 [`제안서_본문.md`](제안서_본문.md) Part 1~5의 문제 A~F와 교차 검증했다. 원칙은 하나다 — **"정확하게 잴 수 있는가"를 통과한 것만 실 KPI로 쓰고, 아직 가설이거나 측정 방법이 불확실한 건 정리만 해두되 KPI 카드에는 반영하지 않는다.**

### 최종 KPI 우선순위 (실측 가능한 것만, v1 대시보드 기준)

| 순위 | KPI | 담당 문제 | 데이터 가공 방법 |
|---|---|---|---|
| **1** | 브랜드 검색지수 | A | NAVER Search Trend API에 "이니스프리" 단일 키워드 요청 → 월간/주간 상대 검색량 지수(0~100) 수신 → 2021~2025 기존 시계열에 이어붙여 MoM/YoY % 계산 |
| **2** | "제주" 연상 비중 (Heritage Association) | A | NAVER Search Trend API에 ① "이니스프리" 전체 검색량, ② "이니스프리 제주" 계열 검색량 두 건 요청 → ②/① 비율 계산 |
| **3** | 제품↔브랜드 Gap | D | NAVER Search Trend API에서 ① 브랜드 검색량, ② 대표 제품군(레티놀·그린티 등) 검색량의 전년동기대비 성장률(%)을 각각 구한 뒤 Gap = 제품 성장률 − 브랜드 성장률(%p) |
| **4** | AEO/SEO 대응 상태(구현 여부) | E | 공식 사이트에 자동 HTTP 요청 → robots.txt AI 크롤러 규칙 유무, llms.txt 존재 여부(404 체크), 주요 페이지 JSON-LD(FAQPage 스키마) 존재 여부를 Boolean 판정 → 체크리스트 충족률(%) 집계 |

1~3위는 같은 NAVER Search Trend 파이프라인이라 인프라 하나로 전부 커버된다. 4위는 소비자 반응이 아니라 **회사가 숙제를 했는지 확인하는 실행 지표**라 성격이 다르므로, 화면에서도 별도 구역으로 분리한다.

### 0-1. KPI 목표치 (90 / 180 / 360일 게이트)

Part 5의 게이트 구조(90/180/360일)를 그대로 따른다. 절대 숫자를 임의로 정하지 않고, **지금까지 확인된 실측치에서 역산**했다.

| KPI | 현재값(baseline) | 90일 목표 | 180일 목표 | 360일 목표 | 목표 설정 근거 |
|---|---|---|---|---|---|
| 브랜드 검색지수 | **2.30**(2025년 연평균 실측치 — [네이버데이터랩_검색량_분석_2021-2025.md](../02_수집자료/네이버데이터랩_검색량_분석_2021-2025.md)에 이미 확보돼 있던 값. 앞서 "약 3.2 추정, API 재조회 필요"라고 썼던 건 기존에 이미 수집된 2025년 실측치를 표에 반영하지 않은 것이었음 — 재조회 불필요) | 다음 YoY 낙폭이 -28.8%보다 축소 | YoY 감소율 -10% 이내로 개선(반등 초입) | YoY 플러스 전환. 2023년 수준(5.25) 재도달을 상한 목표로 | 2022(-18.9%)→2023(-23.9%)→2024(-38.5%)→2025(-28.8%)로 **4년 연속 하락**. 다만 2025년 낙폭(-28.8%)이 2024년(-38.5%)보다 이미 줄어든 상태라, 캠페인 없이도 자연 감속이 진행 중이었을 가능성이 있다 — 90일 목표를 "낙폭 축소"로만 잡으면 캠페인 효과 없이도 달성된 것처럼 보일 위험이 있다. **KR2와 같은 논리로, 이후 실측 낙폭을 그냥 "축소됐는가"가 아니라 "자연 감속 추세보다 더 축소됐는가"로 판정해야 한다** — 다음 데이터 포인트가 나오면 감속 기울기 자체를 다시 계산할 것 |
| "제주" 연상 비중 | 1.87%(2025년 최근 확인값) | 최소 1.87% 이상 유지(상승세가 꺾이지 않는지 확인) | 자연 상승 추세(연평균 +0.27%p)보다 빠른 상승 확인 | **2.3% 이상** (개입 없이 추세만 이어졌을 때의 예상치 2.14%를 웃도는 수준) | 2021(0.79%)→2025(1.87%)는 회사 개입이 거의 없던 시기에도 오른 수치라, 목표는 "얼마나 올랐는가"가 아니라 **"자연 추세보다 캠페인이 얼마나 더 끌어올렸는가"**로 잡아야 성과를 왜곡 없이 볼 수 있다 |

> **[제안서_본문_편집용.docx](제안서_본문_편집용.docx)의 "✏️ 팀 작성 필요 — KPI 목표치" 표는 이 4개 KPI 기준으로 다시 채워야 한다** — 그 표는 KPI가 확정되기 전(브랜드검색지수·제주연상비중·접점 수·헤리티지언급률 4종)에 만든 것이라 지금 기준과 다르다.

### 가설 / 보류 — 정리만 해두고 실 KPI에는 미반영

| 항목 | 왜 보류인가 |
|---|---|
| Heritage Content Share(헤리티지 콘텐츠 비중) | 판정 기준이 수동 판독이거나 키워드 매칭 근사치라 정밀도가 낮음 — "이게 헤리티지 콘텐츠다"를 정확히 가를 방법이 아직 없음 |
| Brand Touchpoint Index(오프라인 유입) | 정확한 부분(매장 수)은 이미 "영업 레버, 마케팅 KPI 아님"으로 뺐고, 나머지(실제 방문객 수)는 데이터 소스 자체가 없음 |
| Competitive Search Share(경쟁사 검색 점유율) | 메타 광고에서 "미샤" 검색이 패션 브랜드 MICHAA와 섞였던 것과 같은 동음이의 오염 가능성이 네이버 검색에도 있을 수 있음 — 검증 전 |
| Brand Buzz / Sentiment | 감성분석 자체의 정확도 한계 + 캠페인·논란으로 쉽게 튀는 값이라 해석이 불안정 |
| Heritage Content → Association → Gap → Search 인과 사슬 | 회사발 콘텐츠가 0/220건이던 시기에도 "제주" 연상은 오히려 상승(0.79%→1.87%)한 것으로 관측돼, 오히려 반대 방향의 증거가 있음 — 가설 단계 |
| 브랜드평판 순위·세부지수(참여·미디어지수) | 데이터 소스 표 B등급 이하가 스크롤로 잘려 소스 확인 전 — 확인되면 위 순위표로 승격 검토 |

## 1. 정보구조 — 화면 2개

```
대시보드
├── 화면 1. 분석 재현 화면
│   목적: "우리가 무엇을 근거로 이 제안을 했는가"를 청중이 직접 조작하며 재확인
│   데이터: 이미 확정된 과거 데이터(2021~2025) — 새로 수집할 필요 없음
│
└── 화면 2. KPI 모니터링 화면
    목적: 제안 승인 이후 "약속한 대로 되고 있는가"를 계속 추적
    데이터: 위 KPI 표의 S/A등급 소스에서 매일·주간 자동 수집
```

두 화면은 데이터 흐름이 다르다 — 화면 1은 **한 번 만들면 끝**(과거 데이터, 정적), 화면 2는 **계속 갱신되는 파이프라인**(현재+미래 데이터, 동적)이 필요하다. 구축 난이도도 이 차이에서 갈린다.

**원칙**: 상관계수가 들어간 차트는 숫자만 크게 보여주지 않는다 — [전략실행_지표반응_중립분석.md](전략실행_지표반응_중립분석.md)에 이미 정리된 "다른 설명 가능성"을 짧은 캡션으로 반드시 같이 노출한다. 원본 문서를 안 읽은 청중이 화면만 보고 "상관계수 = 인과관계"로 오해하지 않게 하는 최소 장치다.

## 3. 오프라인 유입 — 데이터 없는 상태를 어떻게 다룰 것인가

이 항목만 유일하게 자동화 소스가 없다. 세 가지 선택지가 있다.

1. **신규 계측 도입**: 공병공간 등 체험 거점에 방문객 카운터·QR 체크인을 설치해 직접 수집 시작(v2 목표)
2. **간접 대리 지표로 근사**: 네이버 플레이스(지도) 리뷰 수·방문자 인증 수를 크롤링 — 데이터 소스 표에 없는 소스라 팀 논의 필요
3. **v1에서는 빈 카드로 둔다**: "아직 측정 체계 없음 — v2 계측 예정"이라고 명시하고, 매장 수(배경 지표)로만 대체 표시

**권장**: v1은 3번으로 시작하고, 대시보드 자체를 발표할 때 "이 지표는 지금 측정 체계가 없다는 것 자체가 하나의 발견"이라고 정직하게 제시하는 편이 낫다 — 없는 데이터를 억지로 채우는 것보다 설득력이 있다.
