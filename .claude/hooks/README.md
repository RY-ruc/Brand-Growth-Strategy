# 주장 검증 훅

**검증되지 않은 주장이 문서에 확정형으로 들어가는 것을 저장 직전에 막는다.**

발표 자료에 틀린 수치가 한 줄만 남아도 심사에서 통째로 무너진다.
이 훅은 그것을 사람 기억이 아니라 기계가 잡게 한다.

## 구성

| 파일 | 역할 |
|---|---|
| `claims.json` | **주장 대장.** 각 주장의 상태와 대체 표현. 팀이 관리하는 것은 이 파일이다 |
| `claim-guard.ps1` | 검사기. `PreToolUse(Write\|Edit)`로 붙는다 |
| `../settings.json` | 훅 등록 (저장소를 직접 열었을 때) |

작업 폴더가 저장소 상위(`이니스프리_리브랜딩분석`)일 때는
`이니스프리_리브랜딩분석/.claude/settings.json`이 절대경로로 같은 훅을 건다.

## 상태 세 가지

| 상태 | 뜻 | 훅 동작 |
|---|---|---|
| `verified` | **실측.** 재현 스크립트로 확인됨 | 검사하지 않는다 |
| `unverified` | **미검증 가설.** 추론일 뿐 | 확정형으로 쓰면 막는다. `가설`·`❓`·`검증 중` 표시가 있으면 통과 |
| `refuted` | **반증됨.** 틀린 것으로 확인 | 철회 맥락(`🚫`·`반증`·`철회`·`틀렸`) 없이 쓰면 막는다 |

## 면제 규칙

매칭된 줄의 **앞뒤 3줄** 안에 그 규칙의 `exempt` 패턴이 있으면 통과시킨다.
철회를 기록하는 문서 자체가 자기가 철회한 문장 때문에 막히면 안 되기 때문이다.

## 새 주장을 등록하는 법

`claims.json`의 `claims` 배열에 추가한다.

```json
{
  "id": "짧은-식별자",
  "status": "verified | unverified | refuted",
  "pattern": "걸러낼 정규식",
  "why": "왜 이 상태인지 — 수치와 함께",
  "instead": "대신 쓸 표현",
  "exempt": "이 패턴이 근처에 있으면 통과",
  "source": "근거 문서 경로 (없으면 null)"
}
```

**`verified`로 올릴 때는 반드시 재현 스크립트를 `02_수집자료/`에 함께 넣는다.**
스크립트 없는 수치는 실측이 아니다.

## 걸렸을 때

훅이 이렇게 돌려준다.

```
주장 검증 훅이 저장을 막았습니다 — 01_분석결과/발표덱.md

[반증됨] 부르면-온다  (line 3)
  걸린 문장 : 회사가 부르면 사람이 온다...
  이유      : 레티놀 상승은 카테고리 +159% 성장의 결과였다...
  대신 쓸 것: 회사는 커지는 시장에 가서 몫을 잃고 있다
  근거 문서 : 01_분석결과/부르면_오는가_인과검증.md
```

셋 중 하나를 한다.

1. `대신 쓸 것`의 표현으로 바꾼다
2. 미검증 가설이면 `가설`·`❓`·`검증 중` 표시를 붙인다
3. 새 실측 근거가 나왔다면 `status`를 `verified`로 바꾼다 (재현 스크립트 필수)

## ⚠ 고칠 때 주의

**`claim-guard.ps1`은 순수 ASCII로 유지할 것.**

PowerShell 5.1은 BOM 없는 `.ps1`을 ANSI로 읽는다.
한글 식별자나 문자열을 넣으면 전부 깨져서 파싱 에러로 훅이 통째로 죽는다
(죽으면 검사 없이 통과하므로 조용히 무력화된다).
**한글 문구는 전부 `claims.json`에 두고, 스크립트는 그것을 UTF-8 바이트로 읽는다.**

## 시험

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/claim-guard.ps1 < 시험입력.json
```

`시험입력.json`은 `{"tool_name":"Write","tool_input":{"file_path":"...","content":"..."}}` 형식이다.
막히면 exit 2, 통과하면 exit 0이다.
